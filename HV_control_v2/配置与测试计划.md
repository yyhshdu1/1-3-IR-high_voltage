## 2. 这一阶段做过的固件与脚本改动

1. **`h`/`H` 改成 `e`/`E`**（FW 2.7）：`e 1` = 使能 HV，`e 0` = 关；`E` 读状态。`h`/`H` 回 `ERR USE_E`，防止旧程序误用。
2. **v1 的 HV_enable 也是低有效**，板上引脚逻辑没变。旧 v1 命令是裸的 `h0` = 开、`h1` = 关（2023-04 的 `HV_test.hdf` 里 P/Q 段 `h1`、R/S 段 `h0` 可证）。之前「v1 每次开机就使能 HV」的说法是错的：v1 的 `setup()` 把 HV_enable 写高 = 关。
3. **时钟下溢 bug 修复**（FW 2.8，2.7 及以前都有）：旧代码先读 `millis()` 再处理串口，命令处理里再读一次，中间跳 1 ms 会让 `now - last_host_ms` 下溢成约 49 天，`timeout`（0x04）/`xtimeout`（0x40）随机误触发。现在先处理串口、再读时钟，并改成有符号差比较。
4. **`test_xray_bench.py`** 新增回归测试：`c timeout 2` + 15 s 连续 `k`（约 321 条）不得触发；3 s 静默必须触发 0x04；`c xtimeout 2` + 15 s 连续 `x 0` 不得触发 0x40。
5. **`bringup_stages.py`、`hv_bringup_gui.py`** 全部改用 `e`；阶段 6 先检查 `h 0`、`h 1`、`H` 都回 `ERR USE_E`。
6. **GMC-800** 作为 X 射线联锁源（只当联锁，不当真实剂量）；RadEye 假读数过滤（`DoseFilter`）。
7. **`首次上电步骤.md`**：新增「固件 2.7」一节和「保护分层」一节；1b 标题要求装转接板后重做。

## 3. 真板上已保存的设置（FW 2.8）

| 参数 | 值 | 说明 |
|---|---|---|
| `timeout` | 10 | 主机心跳：HV 开时每 <10 s 必须发任意命令（如 `k`），否则固件按 `down` 速率降压并锁 0x04。固件出厂默认 0 = 关 |
| `sthr` | 2500 | 打火阈值，约 37.5 µA。EEPROM 里的值不会因为重新烧录而改变，已在板上手动设置并 `c save`，复位后核对过 |
| `cable` | 0 | J1 空载测试时保持 0；接 TOF3000 时才设 1 |
| `scale / dacmax / vprogmax / up / down` | 0.9058 / 59055 / 10.5 / 1000 / 4000 | 出厂默认，未改 |
| `pol` / `name` | **待核对** | 用 `?` 看 `Name` 和 `Pol`，接电源前必须确认和那台 TOF3000 的极性一致 |
| `ethr / spark / sparkwin / backoff` | 100 / 0 / 60 / 1968 | `spark 0` = 只计数不回退；阶段 8 再改 |
| `xthr / xback / xtimeout` | 0（关）/ 3936 / 0（关） | 阶段 8 之前不启用 |

> 以上未标「已验证」的默认值来自指南，没有在这次会话里逐项读回。**下次连板子先发 `c` 或 `s` 把全部配置抄一遍存档。**

### 4.3 已知的未解之谜

- **拔 USB 后 v_prog 为什么变成 0 V：原因不明。** MAX5216 理论上失电保持最后一个输出码，但实测归零。不要依赖这个行为，也不要反过来假设它一定归零。
- ADC 全 65535（12.2878 V）或全 0（-12.2882 V）是 ADC 死掉的特征（隔离器 HV 侧掉电或 Arduino 掉电），会触发 `flt=0x11` 或 `0x13` 并进入 safe_shutdown。第一次测 J1-12 时出现过。
- 真板曾经在 IDE 烧录后丢过 EEPROM 配置，原因没查。

## 5. 保护分层（谁在什么情况下关高压）

| 情况 | Nano 有电？ | 谁关 | 状态 |
|---|---|---|---|
| PC 程序卡死、串口被占用、Windows 睡眠但 USB 仍供电 | 有 | 固件心跳 `timeout` | bench 通过；真板已设 10 s；带高压未测 |
| X 射线读数停止到达 | 有 | `xtimeout`（0x40） | bench 通过；带高压未测 |
| 火花、X 射线超限、v_prog 超限、ADC 失效、线缆脱落 | 有 | 固件联锁 | bench 和真板通过；带高压未测 |
| USB 拔掉、PC 关机 | **无** | 隔离器输入侧无电时输出默认高 → HV_enable 高 = 关 | **J1-12 = 5 V 已实测**；TOF3000 在 5 V 下是否真关断**未验证** |
| TOF3000 收到约 5 V 高电平后是否真的关断 | — | TOF3000 自身 | **未验证（阶段 7 的 1b）** |

要点：

- 心跳只覆盖「Nano 有电、PC 程序不管事」。断电情况下心跳不运行，靠隔离器默认电平。
- 开着心跳时，控制程序必须定时发 `k`。降压按 `down`（约 2 kV/s）走，30 kV 需约 15 s，不是瞬间。
- USB 隔离器只隔离地，不触发关断。
- DB15 转接板是浪涌/静电/过压保护，用来减少打火经 J1 线缆耦合造成的 Arduino 复位或 USB 掉线，**不是断联关高压电路**。参数是设计值，最终订货版本没有再核对。
- 固件所有 `timeout`/`xtimeout` 类保护都要求 FW ≥ 2.8。

## 6. 后续测试计划

按顺序做，前一项没通过不要往下走。

### A. 负极性那块板（不接 TOF3000）

1. 烧 FW 2.8 真版本。
2. 设置并保存：`c pol 0`、`c name TOF-`、`c sthr 2500`、`c timeout 10`、`c save`。
3. `?` 核对 `Name TOF-`、`Pol -`。
4. 阶段 3、阶段 6（`run_stage.py 3 <口>`、`run_stage.py 6 <口>`），J1-12 万用表 `e 1`/`e 0`，拔 USB 测试。
5. 复位后核对 `Pol`：负极性板的极性脚在复位期间会变成「正」。

### B. 正极性板补充

1. 读回并存档全部配置（`s`、`c`），核对 `Name`/`Pol`。
2. 查 EEPROM 丢配置的原因：下次 IDE 烧录前后各读一次 `c`，比较。
3. 示波器看 J1-12 的上电/复位瞬态（拔 USB、插 USB、24 V 开关各一次），确认没有会让 TOF3000 误使能的低电平毛刺。
4. 查 24 V 先上电 / USB 先上电两种顺序下 DAC 和 v_prog 的状态。

### C. 阶段 7：接真实 TOF3000，仍不接 HV 负载

先查手册：24 V 电流、HV_enable 逻辑与高电平门限、polarity 逻辑、v_mon/i_mon 量程、是否有泄放电阻。

1. 先不带转接板：接线逐脚量通，台式电源限流按手册设置。
2. `c cable 1`、`c save`；确认 J1-13 接线。
3. **1b 关断有效性测试**：`e 0` 状态下 `d 1000`，v_mon 必须仍约 0 V；再 `e 1`，v_mon 升到约 0.17 V。5 V 关不掉就停，先改硬件，不要靠 `e 0` 保证无高压。
4. 阶梯爬升到 5 kV（0.2/0.5/1/2/3/5 kV，每步 30 s），v_mon/目标偏差 >3 % 要查，每步看 `flt`、`ev`、台式电源电流。
5. 极性翻转测试（HV 关、DAC=0）。
6. **装上 DB15 转接板后把 1b 重做一遍。** 2023 年数据显示 HV_enable 上并 1 kΩ 会让 5 V 关断失效，转接板在它上面串了 220 Ω。
7. **在 TOF3000 端实测拔 USB 的行为**：`e 1` + `d 1000`（约 0.5 kV）后拔 USB，v_mon 必须降下来，同时记录 v_prog。

### D. 阶段 8：X 射线与带高压联锁

1. 台架上用 `SIM` 和模拟读数先走一遍，再接 GMC-800。
2. `python xray_guard.py --source gmc800 --port COM8 --raw` 看原始读数，本底应约 0.25 次/s（约 0.1 µSv/h）。
3. 先设 `c xthr 40`、`c xtimeout 5`、`c xback 3936`，在 15–20 kV 以下观察，**GMC `xthr` 要用实测本底和真实 X 射线数据再调**。
4. 打火联锁：`c ethr 100`、`c sthr 2500`、`c spark 3`、`c sparkwin 60`、`c backoff 1968`，先 `spark 0` 只计数，确认阈值合理再启用回退。
5. 心跳带高压测试：HV 开着时杀掉 PC 程序，看固件是否按 `down` 速率降压并锁 0x04；`xtimeout` 同理（停掉转发程序）。
6. 两块板同时升压时用 `xray_guard.py --hv-port 板1 板2` 同时转发。

### E. 转接板效果评估

1. 带和不带转接板各做同批打火实验。
2. 每次打火后读 `s`：`rst`、`n_por`、`n_bor`、`n_ext`、`n_wdt`、`n_sw` 有没有增加。
3. 区分「Arduino 复位」和「只有 USB 断了」：如果复位计数没增加但 USB 掉线，说明问题在 USB/隔离器一侧，转接板帮不上忙。

### F. 控制程序

1. 新驱动适配 FW 2.x：`e 1` 使能、换行协议、双板、每 <`timeout` 秒发 `k`；旧生产驱动用的是 v1 裸 `h0` 协议，**与 FW 2.x 不兼容**。
2. 每次连接和每次打火后记录复位计数。
3. 决定是否把真板的 `timeout` 从 10 s 降到 3–5 s（降得越低，PC 卡顿时越容易误触发降压）。

## 7. 开放问题

- 以前遇到的掉线，是 Arduino 复位了，还是只有 USB 断了？（决定转接板有没有用）
- 拔 USB 后 v_prog 归零的原因。
- TOF3000 在约 5 V（经转接板后更低）下能否可靠关断。
- v1.4 要不要处理极性默认值（默认低档隔离器只用于 polarity；HV_enable 和 relay_ctl 不能改成默认低，会变成使能或吸合）。
- 积分器没有 10 V 钳位，v1.4 建议在 J1-2 前加 10 V 左右钳位。
